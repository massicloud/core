في MassiCloud ثلاثة أدوار ستتعامل معها: **anon** و**authenticated** و**service_role**. فهمها هو أهم خطوة في تعلّم المنصة.

## الأدوار الثلاثة

| الدور           | من               | ما يمكنه فعله                                                                 |
| --------------- | ---------------- | ----------------------------------------------------------------------------- |
| `anon`          | أي شخص           | ما تسمح به سياسات RLS للدور `anon`                                            |
| `authenticated` | مستخدم مسجّل     | ما تسمح به سياسات RLS للدور `authenticated`، محدودًا لذلك المستخدم عبر `auth.uid()` |
| `service_role`  | خادمك            | كل شيء — يتجاوز جميع قواعد RLS                                               |

الدور لأي طلب يُحدَّد بالمفتاح + الرمز المُرسلَين.

## كيف يحصل الطلب على دور

كل طلب API يتضمن ترويسة `X-MassiCloud-Key` — إما **مفتاح anon** أو **مفتاح service**:

```
X-MassiCloud-Key: mc_anon_xxxxx
```

هذا وحده يمنح الطلب الدور `anon`.

للحصول على الدور `authenticated`، يتضمن الطلب أيضًا ترويسة `Authorization: Bearer <jwt>` مع JWT من `signIn`:

```
X-MassiCloud-Key: mc_anon_xxxxx
Authorization:   Bearer eyJhbGc...
```

الآن يُنفّذ Postgres الاستعلام بـ `role = 'authenticated'` ويعيد `auth.uid()` معرّف المستخدم.

للحصول على `service_role`، أرسل مفتاح service مباشرةً:

```
X-MassiCloud-Key: mc_service_xxxxx
```

هذا يتجاوز جميع قواعد RLS — استخدمه فقط من كود خادم موثوق.

## المفاتيح

- **مفتاح anon** (`mc_anon_...`) — عام. يمكن شحنه في المتصفحات والتطبيقات المحمولة. بمفرده لا يستطيع سوى ما تسمح به سياسات RLS.
- **مفتاح service** (`mc_service_...`) — سري. لا ترسله أبدًا في كود العميل. يتجاوز RLS.

إن سرّبت مفتاح service عن طريق الخطأ، قم بتدويره فورًا من صفحة مفاتيح API في البوابة.

## مصادقة المستخدمين النهائيين

المستخدمون النهائيون يسجّلون ويدخلون عبر endpoints المصادقة. SDK يغلّفها:

```js
await massi.auth.signUp({ email, password })
await massi.auth.signIn({ email, password })
await massi.auth.signOut()
```

هذا يخزّن المستخدم في جدول `auth.users` في Postgres الخاص بمشروعك ويعيد JWT موقّعًا بسرّ مشروعك. SDK يدير هذا الرمز تلقائيًا.

## ما يُخزَّن وأين

| ما                                         | أين                                              |
| ------------------------------------------ | ------------------------------------------------- |
| تسجيل دخولك للمنصة (أنت، المطوّر)          | خطة التحكم المركزية لـ MassiCloud                |
| مفاتيح API للمشروع (anon، service)         | خطة التحكم لـ MassiCloud                        |
| حسابات المستخدمين النهائيين (عملاء تطبيقك) | Postgres الخاص بك في `auth.users`               |
| JWTs المستخدمين النهائيين                   | جانب العميل، مُدار بواسطة SDK                   |

المستخدمون النهائيون مقيّدون بالمشروع — يعيشون في قاعدة بيانات tenant خاصتك، لا في نظام مركزي مشترك.
