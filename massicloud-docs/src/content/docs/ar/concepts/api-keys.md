---
title: مفاتيح API
description: فهم مفاتيح anon وservice في MassiCloud.
---

كل مشروع يمتلك مفتاحَي API، مشتركين بين جميع قواعد بيانات المشروع — Postgres وMySQL على حد سواء. يُحدّدان الدور المُستخدم للطلبات ويتحكّمان في الوصول إلى بياناتك. بقية هذه الصفحة تصف نموذج دور Postgres وRLS؛ قواعد MySQL تستخدم نموذجًا أبسط بدورين بلا معادل لـ RLS — راجع [المصادقة: مثيلات MySQL](/ar/concepts/authentication).

## مفتاح anon (`mc_anon_…`)

آمن للتضمين في كود المتصفح والتطبيقات المحمولة. يمنح فقط دور Postgres `anon`، ما يعني أن الطلبات تخضع لسياسات RLS.

استخدم متغيرات البيئة لتجنب الترميز الثابت:

```js
// Vite
const massi = createClient({ key: import.meta.env.VITE_MASSI_KEY, ... })
```

## مفتاح service (`mc_service_…`)

لا تكشفه أبدًا في كود العميل. يمنح دور Postgres `service_role` الذي يتجاوز جميع سياسات RLS. استخدمه لـ:

- مسارات API من جانب الخادم
- الوظائف والعمال في الخلفية
- سكريبتات الإدارة والترحيلات

## تدوير المفاتيح

اذهب إلى **المشروع ← مفاتيح API ← تدوير** في البوابة. المفاتيح القديمة تتوقف عن العمل فورًا.

## ماذا يحدث إذا سُرّب مفتاح

إن سُرّب مفتاح anon، دوّره. الضرر محدود بسياسات RLS.

إن سُرّب مفتاح service، دوّره فورًا — يتجاوز جميع قواعد RLS. عامله كبيانات اعتماد قاعدة بيانات root.
